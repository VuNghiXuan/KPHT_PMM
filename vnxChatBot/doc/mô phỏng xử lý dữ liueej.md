Tổng quan cách thức hoạt động của document_processor.pyKhi tài liệu (Word, PDF, Excel) được người dùng tải lên nhóm, hệ thống không cho phép xử lý trực tiếp trên HTTP Request để tránh nghẽn nghẽn cổ chai. Thay vào đó, Celery Task (process_document_task) sẽ gọi đến DocumentProcessorService.Quy trình xử lý diễn ra qua các bước:Nhận diện định dạng: Xác định phần mở rộng file (.pdf, .docx, .xlsx, .txt).  Trích xuất thông minh:Đối với file PDF/Word phức tạp: Sử dụng Docling/Marker để bóc tách và chuyển đổi toàn bộ cấu trúc văn bản sang định dạng Markdown sạch, giữ nguyên cấu trúc bảng biểu (Tables).  Đối với file Excel: Sử dụng ExcelSemanticParser để thực hiện Context Clustering (gom cụm ngữ cảnh), chuyển đổi các dòng dữ liệu thành dạng phân cấp thay vì bảng dạng lưới thô.  Phân rã khối (Chunking): Cắt nhỏ văn bản thành các đoạn có kích thước tiêu chuẩn (ví dụ: 1000 ký tự với 200 ký tự chồng lấp - overlap) để phục vụ cho việc tìm kiếm ngữ nghĩa sau này.  Lưu trữ Staging & Kiểm toán (AI Data Auditor): Dữ liệu sau khi trích xuất sẽ được lưu vào bảng trung gian RawDocument ở trạng thái STAGING để AI chấm điểm tin cậy (Confidence Score) và tạo cây mục lục nháp (raw_structure_json), tuyệt đối chưa đẩy vào Vector Store.  2.
